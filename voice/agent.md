## 1. Create the agent

- [ ] Build → create a new agent from scratch (not Genie), name `Jodi`, description "Postpartum + newborn voice companion, 42 days (hackathon demo, synthetic data)".
- [ ] Keep it **single-state** (Sarvam recommends starting single-state).

## 2. Instruction (Canvas → Instruction)

**Greeting** (played as-is, not generated by the LLM; one translation per language via **Translations**). Keep it neutral, because it plays for every mode (including unknown and wrong-person callers):

| Language | Greeting (draft, native speaker to check) |
|---|---|
| Kannada | ನಮಸ್ಕಾರ, ನಾನು ಜೋಡಿ. (Namaskara, naanu Jodi.) |
| Hindi | नमस्ते, मैं जोडी हूँ। (Namaste, main Jodi hoon.) |
| English | Hello, this is Jodi. |

- [ ] Do not put `{{mother_name}}` in the greeting: a wrong person or unknown caller would hear it.
- [ ] **Instructions** = `prompts/system.md` (from `=== BEGIN INSTRUCTIONS ===`) followed by the playbooks `onboarding.md`, `checkin.md`, `inbound.md`, `asha.md`, `doctor.md`, `unknown.md`, `family_alert.md` (each from its `=== BEGIN ===` line) under "Mode playbooks".
- [ ] Replace every `{{variable}}` with a variable chip (`@`), and every tool name with a tool chip (`@`).
- Variable syntax: the docs show `{{user_name}}` (voicemail message) and `{user_name}` chips (greeting). In the editor you insert chips with `@`, so the text form does not matter.

## 3. Speaking (Settings → Speaking / Speakers & voice)

- [ ] **TTS model: Bulbul V4.** Never Bulbul V3: it reached end of life on Voice Agents on **10 Nov 2026**.
- [ ] **Voice:** a calm, warm, female voice that sounds natural in Kannada. Preview candidates in the V4 catalog (filter by language). Names from the V3→V4 mapping worth previewing: "Kavya - Conversational Voice", "Shreya - Conversational Voice", "Kavitha - Narrator", "Roopa - Narrator", "Priya - Recovery Agent". Which of these speak Kannada well is **[docs: not specified]**: a native speaker should choose. Chosen voice: _TBD_.
- [ ] **Per-language voices** (optional): map Kannada / Hindi / English to warm female voices. The speaker stays the same for the whole call even after a language switch.
- [ ] **Speaking speed:** start at 0.95x (slower for elderly family members and phone audio); tune after test calls.
- [ ] **Pitch:** 0.00. **Volume:** 1.0–1.2 (range 0.7–2.0).
- [ ] **Pronunciation dictionary** (JSON, per language, Indic-script spellings): add "Jodi", "ASHA", "labetalol", "108", facility names. Values to be written by the native speaker. Phonemes are not supported.

## 4. Listening / speech recognition

- [ ] ASR is **Saaras v4** (managed by Sarvam; no model picker). There is also no LLM picker: the reasoning model is routed automatically.
- [ ] **Advanced → Important words** (ASR hotwords), one per entry: `Jodi`, `ASHA`, `batte`, `haalu`, `jvara`, `fits`, `jhatke`, `daura`, `behosh`, `moorchhe`, `haladi`, `labetalol`, `Lakshmi`, `Sunita`, `Ravi`.
- [ ] **Advanced → Detect when the caller stops talking:** on.

## 5. Language personalisation (Settings)

See `tools/language_switch.json`.

- [ ] Starting language: **Kannada**.
- [ ] Switch language during call: **on** (this enables the **language switch** core tool).
- [ ] Languages allowed: **Kannada, Hindi, English**.
- [ ] Auto-detected language switch: **on**; "Switch after": start with the default **[docs: default value not specified]**.
- [ ] Output numbers in Indic: start **off** (BP read as "150 over 100"); test with mothers and switch on if Indic number reading is clearer.
- [ ] Outbound calls: the backend can set the start language per call with Instant Outbound `app_overrides.initial_language_name` (`Kannada` / `Hindi` / `English`).

## 6. Model temperature

- [ ] **0.1–0.2** (towards "Compliant"; default 0.3). We need consistent, rule-following behaviour, not creativity.

## 7. Conversation settings

- [ ] **Let callers interrupt:** **on**. A mother must be able to say "fits" mid-sentence. Trade-off: a caller can interrupt a red script. The prompt tells the agent to finish the red text; re-test this on phones.
- [ ] Sound sensitivity: **Medium**, lower to **Low** if TV or kitchen noise causes false interruptions (test 06).
- [ ] Eagerness to respond: **Patient** (mothers pause, elders speak slowly).
- [ ] Background sound: **No sound**.
- [ ] **Nudge quiet callers:** on. Nudge 1 at 20 s: "Neevu kelistideeya?" (kn draft) / "Kya aap sun rahi hain?" (hi) / "Are you still there?" (en). Nudge 2 at 45 s. The breath count (one full minute) needs a long quiet gap: the prompt tells the agent to wait; check that nudges do not cut in during the count and raise the delays if they do.
- [ ] **Hang up after unanswered nudges:** **off** (a silent line on a danger call must not be dropped by a timer; max call length covers runaway calls).
- [ ] **Max call length:** 15 minutes.
- [ ] **Voicemail:** on, with a message that has **no health information**: "Namaskara, this is Jodi. Please call us back on this number." No variables in it.
- [ ] **Advanced → Protect sensitive info:** on (masks phone numbers in logs).
- [ ] **Knowledge bases:** attach the KB from section 10.

### 8.2 Output variables (extracted after the call; analytics only, the backend does its own extraction)

| Variable | Type | Values | Extraction prompt |
|---|---|---|---|
| `call_outcome` | Enum | `completed`, `red_flag`, `amber_flag`, `no_answer`, `wrong_person` | "Classify the call. red_flag if the agent read an emergency (red) instruction or transferred the call to family. amber_flag if the agent read a 'needs to be checked today' (amber) message and no red one. wrong_person if the person who answered was not the mother, her family, her ASHA or a doctor with her, and the agent ended politely. no_answer if nobody spoke at all. Otherwise completed." |
| `language_used` | String | `kn`, `hi`, `en` or a mix like `kn+en` | "Which language(s) did the caller mainly speak? Answer with codes: kn (Kannada), hi (Hindi), en (English); join with + if mixed, main language first." |

- [ ] **Call goal ("Successful when"):** `call_outcome` `=` `completed`. Red/amber calls will then show as "not successful" in analytics; that is acceptable for the demo. Which other operators are available is **[docs: not specified]** (only `=` is shown).
- `no_answer` can never really be extracted: an unanswered call never reaches the agent. The real no-answer signal is the Instant Outbound webhook `status`.

## 14. Deployment

### 14.1 Inbound (Deploy → Inbounds → Create Inbound)

- [ ] Telephony: **Rent from Sarvam** (Vobiz underneath, so call transfer works with no extra setup).
- [ ] Agent: `Jodi`, the **committed** version that passed Tests. The agent is locked after creation (change only while paused, or make a new deployment).
- [ ] Phone number: assign the Jodi number. Name: `jodi-inbound`.
- [ ] Availability: Timezone **Asia/Kolkata**, Allowed days **all 7**, Calls allowed between **00:00 and 23:59** (the default is 09:00–18:00). **Confirm 24×7 works:** place real test calls at about 23:59 and 00:01. Whether the minute 23:59–00:00 is covered is **[docs: not specified]**.
- [ ] Known callers (optional): not needed, because the on-start hook identifies callers.
- [ ] Review & Deploy.

### 14.2 Post-call webhook

- The **on_end hook** (section 9) sends the contract shape with the bearer token. It is the primary path.
- Backup: set the inbound deployment's `webhook_config.url` (Deployments API, only while paused) to `{{PUBLIC_BASE_URL}}/hooks/sarvam-webhook?token=<TOOL_SHARED_SECRET>`. The backend adapter accepts the Sarvam payload (`attempt_id`, `status`, `interaction_id`, `duration`, `final_agent_variables`, `interaction_transcript[{role, en_text}]`), authenticates with the token (Sarvam webhooks cannot send a bearer header) and runs the same idempotent on-end pipeline. Do not point the webhook at `/hooks/on-end`.

### 14.3 Outbound (backend-triggered)

- Implemented in `backend/app/integrations/sarvam_calls.py`: `POST https://apps.sarvam.ai/api/outbounds/v1/orgs/{org_id}/workspaces/{workspace_id}/outbounds` with `app_config{app_id, app_version, connection_config, agent_variables, app_overrides.initial_language_name}`, `user_config{user_phone_number}`, `webhook_config{url: /hooks/sarvam-webhook, metadata.token}`. Compare it once with Deploy → Deploy with Code before the first live call.
- `agent_variables` carry `call_direction=outbound`, `call_purpose`, `callee_phone`, `mother_id`, `language`.
- The response `attempt_id` is bound to the real `@InteractionID` on on-start (by callee phone) or by the webhook. The webhook `status` (`no_answer`, `busy`, `failed`) starts the missed-call chain.
